  • 段階3.0〜3.2・入力3表パイプラインは廃止（2026 以降）。

1. パイプライン（段階1 / 2.0 / 2.1 / 2.5 / 配台試行）

1.1 段階1

  • 入力: 加工計画DATA など
  • 出力: 配台計画_タスク入力
  • 主要列: 配台可能日時、配台可能日時_上書き、（元）配台可能日時_上書き

1.2 段階2.0（配台A）

  • 開始下限は 配台可能日時_上書き → 配台可能日時 → 原反投入日由来 の順で解決する。
  • 同日下限は DISPATCHABLE_FROM_TIME = 12:45 を適用（13:00は使用しない）。
  • 例外: 湖南工場（PM_AI_FACTORY_SITE=KONAN）かつ在庫場所「湖南」は DISPATCHABLE_FROM_TIME_KONAN_STOCK（既定 9:30）。
  • 両面EC の配台時間:
    • 湖南工場: 両面EC を EC 機械に載せるときは EC 加工2回分（配台時間を倍化）。SEC 機械はワンパスのため等倍。
    • 国分工場（PM_AI_FACTORY_SITE=KOKUBU）: 1パスで両面EC 可能なため、EC 機械でも配台時間は等倍。

1.3 段階2.1（時間外）

  • 残業・休出をウィザードで決めたうえで、段階2（配台A）を実行するシミュレーション。
  • 段階2.0 の事前実行は不要。入力は入力1表（配台計画_タスク入力）。
  • 配台本体エンジンは配台A。勤怠は overtime_simulation_overrides.json で一時上書きする。

1.4 段階2.5（AI 整列・任意）

  • 段階2 成果の配台表を AI/ルールで整列し、結果_配台表.after_stage2_5.json 等へ出力する。
  • 配台A は実行しない。UI 手動ボタンは停止設定のことがある。

2. 納期基準・開始日

2.1 納期基準

① 回答納期 → ② 指定納期。AI による上書きは行わない。

2.2 開始日・配台可能日時

  • 原反: 原反投入日_上書き 優先。
  • 配台可能日時: 上書き列 → 算出列 → 原反日＋12:45（DISPATCHABLE_FROM_TIME）。
  • 同日加工下限も 12:45（旧 13:00 は使用しない）。
  • 湖南工場・在庫場所「湖南」の例外: DISPATCHABLE_FROM_TIME_KONAN_STOCK（既定 9:30）。

3. 休憩・終業直前

  • ASSIGN_END_OF_DAY_DEFER_MINUTES（既定 45 分）と ASSIGN_EOD_DEFER_MAX_REMAINING_ROLLS（既定 5）による終業直前デファー。
  • 同一依頼の連続ロールではデファー免除。
  • 休憩帯内開始・休憩またぎは繰り下げまたは却下。

4. キュー順序

4.1 グローバルキュー

  • task_queue は _generate_plan_task_queue_sort_key 系で整列する。
  • 比較軸: in_progress / due_basis_date / b_tier / b2_queue_sub / need列位置 / 依頼NO。

4.2 日内ループ

  • 既定: STAGE2_DISPATCH_FLOW_TRIAL_ORDER_FIRST=1
  • §B-2 / §B-3 は二相・再走査あり。

5. §A 全依頼共通ルール

A-1 加工内容順

  • 同一依頼NOで 加工内容（カンマ区切り）を工程順として扱う。
  • 先行工程の残ロールがある間、後続工程は原則ブロック。

A-1.2 配台計画タブのエンボスまとめ（手動）

  • 段階1後の配台計画（タスク入力）タブで、ボタン「エンボスをまとめる」を押したときだけ行順と配台試行順番を書き換える。自動では動かない。
  • 同一依頼NO（入力3.0は元依頼NO）の配台対象行は一塊。依頼内は §A-1 のまま（先行工程は当該依頼のエンボス直前）。
  • エンボス行の機械名が同じ依頼塊だけを、その機械で最初に現れたエンボス依頼の位置へ集約する。湖南と国分は混ぜない。
  • エンボスを含まない依頼の前後関係は維持する。配台不要オン行は塊に入れない。
  • 配台対象にエンボスがあるとき、「エンボスをまとめる」をオレンジで点灯する。押したあとは点灯をやめ、未保存の合図として「保存」を点灯する。保存成功後は保存の点灯も消す。

A-2 同一依頼NO直列化

  • rank未確定行は same_request_line_seq（シート行順）で直列化する。

6. §B 個別ルール（現行）

B-1 検査（熱融着機 湖南）加工途中の優先

  • 対象: 検査 × 熱融着機　湖南 かつ in_progress=true

B-2 EC → 検査 ロールパイプライン

  • 対象: 先行 EC × EC機　湖南、後続 検査 × 熱融着機　湖南
  • 初期バッファ、assign_room 制御、再走査（rewind）を適用する。

B-3 EC → 巻返し ロールパイプライン

  • B-2同趣旨で後続工程を 巻返し とする。

B-4 スリット → SEC WIP上限

  • WIP_LIMIT_SLIT_BEFORE_SEC_ROLLS を適用する。

B-5 特別ルール列挙（L系）

  • L系（速度・人数・優先）を適用。詳細は 特別ルール列挙.md。

B-6 接続 → SEC WIP上限

  • WIP_LIMIT_CONNECTION_BEFORE_SEC_ROLLS を適用する。

7. need / surplus

  • need の基本必要人数を基準に配台する。
  • 追加人数は設定でメイン反映または後追記を切替。
  • 主要フラグ: TEAM_ASSIGN_USE_NEED_SURPLUS_IN_MAIN_PASS、TEAM_ASSIGN_IGNORE_NEED_SURPLUS_ROW

8. 未加工・残量算定

  • 未加工 列は必須。解釈不可行はエラー。
  • 換算数量>0 / 実加工数=0 / 未加工=0 は全数未加工として扱う。
  • 最小加工長さはロール単位長さを下回らない。

9. 環境変数（主要）

  • フロー: STAGE2_DISPATCH_FLOW_TRIAL_ORDER_FIRST / STAGE2_SERIAL_DISPATCH_BY_TASK_ID / STAGE2_RETRY_SHIFT_DUE_ON_PARTIAL_REMAINING
  • B系: PLANNING_B1_INSPECTION_EXCLUSIVE_MACHINE / PLANNING_B2_EC_FOLLOWER_DISJOINT_TEAMS
  • WIP: WIP_LIMIT_EC_BEFORE_INSP_ROLLS / WIP_LIMIT_SLIT_BEFORE_SEC_ROLLS / WIP_LIMIT_CONNECTION_BEFORE_SEC_ROLLS
  • 配台試行: PM_AI_INTERACTIVE_TRIAL_STAGE2_PARITY
  • 工場別例外: PM_AI_FACTORY_SITE（KONAN / KOKUBU。国分は両面EC 配台時間等倍） / DISPATCHABLE_FROM_TIME_KONAN_STOCK（既定 9:30）
