# 設備ガント担当割当編集 実装計画

## 方針
- 設備ガント契約JSONの `timeline_events.op/sub` を、現在成果物に対する編集正本とする。
- 既存の「バッジ位置調整」と新しい「担当割当編集」を別モードにする。
- 空きバーへのドロップはMOVE、バッジ上はSWAP。追加は資格者選択、削除時は先頭補助担当を主担当へ昇格し、0名化は禁止する。
- 資格外・欠勤は警告確認後に強制可能、同時間帯の二重割当は保存不可とする。

## 実装
1. [EquipmentGanttContractSheetTableBuilder.java](code_java/src/main/java/jp/co/pm/ai/desktop/io/gantt/EquipmentGanttContractSheetTableBuilder.java) と [EquipmentGanttSheetBundle.java](code_java/src/main/java/jp/co/pm/ai/desktop/io/gantt/EquipmentGanttSheetBundle.java) を拡張し、短縮表示名とは別に、フル氏名・主補役割・安定バーID・対象イベント群を持つ編集メタデータを返す。連続バー内の分割イベントは同じ編集単位へ束ねる。
2. 純粋な編集モデルを新設し、MOVE、SWAP、追加、削除、主担当昇格、同一人物重複拒否をTDDで実装する。[EquipmentGraphicGanttPane.java](code_java/src/main/java/jp/co/pm/ai/desktop/ui/EquipmentGraphicGanttPane.java) はモデルIDだけをDragboardへ載せ、業務判断を持たせない。
3. [EquipmentGanttGraphicTab.fxml](code_java/src/main/resources/jp/co/pm/ai/desktop/fxml/EquipmentGanttGraphicTab.fxml) と [EquipmentGanttGraphicTabController.java](code_java/src/main/java/jp/co/pm/ai/desktop/EquipmentGanttGraphicTabController.java) に担当編集モード、追加、削除、保存、元に戻す、未保存表示を追加する。追加候補は既存の `SkillsSheetMemberReader` / `LimitedOperatorChecklistDialog` 系を再利用する。
4. Pythonに担当変更の事前検証・成果物同期CLIを新設する。契約ハッシュ、資格、契約内勤怠、勤務時間、休憩、二重割当を検査し、警告時は書込みせず確認トークンを返す。確認後の再実行では、資格外・欠勤のみ強制を許可する。
5. [stage2_impl.py](code/python/planning_core/core/stage2_impl.py) の人員表生成を再利用可能な関数へ局所抽出し、[roll_pipeline.py](code/python/planning_core/core/roll_pipeline.py) に既存値を上書きする担当者再集計経路を追加する。数量・日付・配台順は変更しない。
6. 同期CLIは設備ガント契約、計画XLSX/JSON、人員XLSX/JSON、結果配台表JSON/XLSXを一時領域へ全生成し、JSON/XLSXの再読込と担当整合を検証する。バックアップとトランザクション記録を作成後、契約JSONを最後に差し替える。Excelロック、ハッシュ競合、途中失敗では元成果物を維持・復旧する。
7. JavaFX側から既存 `PythonProcessRunner` でCLIを非同期実行し、警告確認ダイアログ、失敗理由、保存成功を表示する。成功後に設備ガント、結果配台表、人員表依存のオペレーターカードを再読込する。

## 検証
- Java単体テスト: 契約イベントの編集ID、同姓識別、MOVE/SWAP、追加/削除、主担当昇格、0名拒否、DnD要求変換。
- Python単体・統合テスト: 資格/欠勤警告、確認トークン、二重割当拒否、全イベント同時更新、各成果物の担当一致、ハッシュ競合、Excelロック、ロールバック。
- 回帰確認: 既存の位置調整ドラッグ、印刷/PDF、通常の段階2生成、次回段階2で手動変更がリセットされること。
- 対象テスト後、Java MavenテストとPython関連テストを実行し、編集ファイルのIDE診断も確認する。
