保存前競合検知 — 実装アプローチ

クリックして選択してください（推奨は A）

A

共通ガード + 画面別要約プラグイン（推奨）

読込時に SHA-256 を記録。保存直前に共通 SaveConflictGuard が再ハッシュ。衝突時は共通ダイアログへ、差分本文は画面ごとの ConflictDiffSummarizer が業務語で生成。

Pros

  • UX・検知ロジックが全画面で統一
  • 要約だけ画面固有に分離でき保守しやすい
  • 関連 Excel も同じ指紋で扱える

Cons

  • 初回で要約実装が画面数ぶん必要
  • 横断変更のためレビュー規模が大きい
B

共通ガード + 汎用構造差分フォールバック

ハッシュ検知とダイアログは共通。要約は JSON パス／表セル差分の汎用生成を既定とし、勤怠などだけ業務語に差し替え。

Pros

  • 全画面カバーを早く達成
  • 未対応画面でも最低限の差分は出る

Cons

  • 「業務語要約」要件を一部で満たしきれない期間がある
  • 汎用差分が長くなりがち
C

各コントローラに個別実装

画面ごとにハッシュ比較・ダイアログ・要約を直書き。共通抽象は最小限。

Pros

  • 画面単位で独立に進められる

Cons

  • 挙動のばらつき・重複コードが増える
  • 全画面一気適用には不向き

推奨

A — 「全画面・業務語・SHA-256」を満たしつつ、検知と UI を一本化できるため。
