# 後加工工賃 金額整合性検証

●自動検証フォルダ内の3つのデータソースを突合し、金額の矛盾点をレポートする。
**国分工場と湖南工場で②のExcelフォーマットとフォルダが異なる**ため、`--factory` で工場を切り替えて実行する（スクリプト内の `_factories()` プロファイルで切り分け）。

## フォルダ構成（●自動検証 直下）

| フォルダ | 内容 |
|---|---|
| `東レ送付CSV\` | 東レから送付された `RVSHEETyyyymm.csv`（両工場共通。入庫場所で工場を切り分け） |
| `国分工場\` | 国分工場のデータ群: `長岡後加工賃明細\`（②後加工工賃明細xlsx）/ `アラジン\`（③依頼NO別問合せ） |
| `湖南工場\` | 湖南工場のデータは湖南共有側を直接参照するため、ここには参照先へのショートカット（.lnk）だけが置かれている。スクリプトは .lnk を読まず下表の絶対パスを使う |
| `手動判定.csv` | 人が下した判断（「今回に限り①東レ金額を正とする」等）を月・工場・契約NO単位で記録するファイル。検証Aの不一致に適用される（後述「手動判定」）。無くても実行できる |
| `前月過不足.csv` | 前月の工賃差検証で東レへ次月修正を依頼したが、当月①CSVに調整行が未反映の差額。検証A「前月過不足」として報告計上に含める（後述「前月過不足」） |
| `検証結果_<工場>_*.xlsx` | 本スキルの出力（工場ごとに最新1件を直下に残す） |
| `過去検証結果\` | 最新以外の検証結果 xlsx / html を自動退避するフォルダ |

●自動検証の**外**（`\\192.168.0.101\共有フォルダ\湖南工場\湖南共有\` 配下）を直接参照するもの（湖南工場）:

| ソース | 参照先（スクリプト内の定数） | 探し方 |
|---|---|---|
| ② 加工賃試算 | `002  加工G\000  後加工業務\2 後加工試算\`（`KONAN_SHISAN_ROOT`。フォルダ名の空白は半角2つ） | ルート直下の `月度加工賃試算.xlsm` = **当月の作業中ファイル**、`yyyy年度試算　湖南\m月度加工賃試算.xlsm`（年度=暦年、「試算」と「湖南」の間は全角スペース）= 月末処理後に格納された確定月。対象年の前後1年の年度フォルダも走査し、月はすべてシート内「yyyy年m月度」で判定。同一年月が複数あれば更新日時最新（作業中ファイルが年度フォルダにコピーされても新しい方が採用される）。`temp`・`バックアップ`・`H30年度`等は見ない |
| ③ アラジン | `生産管理システム\管理システム\●DATA\月次実績\`（`KONAN_ALADDIN_DIR`） | `依頼NO別問合せ_yyyymmdd_hhmmss.xlsx`。シート内「対象年月」で月を判定し、同一年月が複数あればファイル名の日時が最新のもの |
| 月次処理ファイル（検証C） | `生産管理システム\アラジンオフィスシステムデータ\月次実績表\0 東レ月次処理ファイル\`（`KONAN_MONTHLY_ROOT`） | 年フォルダ `yyyy年\yyyy年mm月度 湖南工場 月次処理ファイル.xlsm`（ルート直下も見る）。対象月のファイルをファイル名の年月で選択 |

参照先にアクセスできない場合は②③はエラーで停止、月次処理ファイルは警告して検証Cをスキップする。コンソール冒頭とサマリ「使用ファイル」に各参照フォルダを表示する。

## データソースと突合キー

### 国分工場（`--factory kokubu`、既定）

| ソース | 場所 | キー | 金額 |
|--------|------|------|------|
| ① 東レ検収CSV | `東レ送付CSV\RVSHEETyyyymm.csv` の入庫場所 **A010** | 発注No.（=契約NO、`191-352R`形式） | 金額列（10列目） |
| ② 長岡明細 | `国分工場\長岡後加工賃明細\後加工工賃明細（yyyy年m月度)Vnn.xlsx` の「東レまとめ」シート | 依頼NO = A列&"-"&B列 / 契約NO = C列（`191352R`形式） | AA列（加工賃合計） |
| ③ アラジン | `国分工場/アラジン/依頼NO別問合せ_*.xlsx` | 依頼NO列（`C7-52`形式） | 項目「加工金額」行の「--合計--」列（倉庫では絞り込まない） |

### 湖南工場（`--factory konan`）

| ソース | 場所 | キー | 金額 |
|--------|------|------|------|
| ① 東レ検収CSV | 同じ `RVSHEETyyyymm.csv` の入庫場所 **A010P** | 同上 | 同上 |
| ② 加工賃試算 | 後加工試算ルート（`KONAN_SHISAN_ROOT`）の `月度加工賃試算.xlsm`（作業中）/ `yyyy年度試算　湖南\m月度加工賃試算.xlsm`（確定月）の「東レT.V.C」「東レY.S」「東レW.E..」3シート（合算） | 依頼NO = A列「加工依頼No.」（`C8-1`形式） / 契約NO = C列「契約No.」 | 「加工種類別 加工賃」の合計列（V列） |
| ③ アラジン | 月次実績フォルダ（`KONAN_ALADDIN_DIR`）の `依頼NO別問合せ_*.xlsx` | 依頼NO列 | 同上。ただし **得意先=049006（東ﾚ(株) 自材部）の行のみ**（TPI 049052 等が混在するため。倉庫では絞り込まない） |
| 月次処理ファイル | 東レ月次処理ファイルルート（`KONAN_MONTHLY_ROOT`）の `yyyy年\yyyy年mm月度 湖南工場 月次処理ファイル.xlsm` | （契約NO等の明細なし） | 「月次検証」シート東レ行の 月次実績①(Excel)/月次実績表②(アラジン)/売上明細③ と「集計表」東レ合計の加工金額 |

- 湖南②のファイル名には年が無い（作業中ファイルは月すら無い）ため、対象年月は東レシート先頭の「yyyy年m月度」セルから読む。ヘッダー行（A列「加工依頼No.」）の3行下が合計行、4行下からデータ行。シートの合計行とデータ行合計を検算し不一致なら警告。
- 湖南②の運用: 当月は `2 後加工試算\月度加工賃試算.xlsm` で作業し、月末処理後に `yyyy年度試算　湖南\m月度加工賃試算.xlsm` として格納される。したがって当月分は作業中ファイルから取れる（年度フォルダにまだ無い）。コンソール・サマリでは②のファイル名をルートからの相対パス（`2026年度試算　湖南\7月度加工賃試算.xlsm`）で表示して両者を区別する。
- 湖南の月次処理ファイルは明細が無いので **検証C** として東レ合計の総額だけを照合する: 月次実績①(Excel) と 集計表東レ合計 ↔ ②試算3シート合計、月次実績表②(アラジン) ↔ ③アラジン東レ分合計、売上明細③ ↔ ①東レCSV総額（差は報告用内訳＝前月調整+翌月記載+当月差異+未解明 で説明できれば「内訳で説明可」、できなければ「要確認」）。結果はサマリの検証Cセクションに表形式で出す。
- 検証A/B のロジック・判定・Excel構成は両工場共通。シート名・ガイド・メール文面の「②長岡明細/AA列」「②加工賃試算/加工賃」等の文言はプロファイルから自動で切り替わる。

### 検証の一覧

| 検証 | 対象工場 | 内容 |
|---|---|---|
| **A** | 両工場 | ① vs ② を契約NOで突合（前月調整・翌月記載の自動判定を含む） |
| **B** | 両工場 | ② vs ③ を依頼NOで突合（複数月累計での月ずれ解消・枝番統合を含む） |
| **C** | 湖南のみ | 月次処理ファイルの東レ合計 vs 本検証の総額 |
| **D** | 国分のみ | ②「東レまとめ」の内部整合性（元4シート 東レT/東レV.C/東レY/東レW.E との参照・式・金額突合） |

- **検証A**: ①↔② を契約NOで突合（ハイフン除去して比較）
- **検証B**: ②↔③ を依頼NOで突合
- **検証D（国分）**: 国分②の「東レまとめ」は元4シートの各行を `=東レT!A6` のように列ごとに参照し、G（単価合計 `=SUM(H:X)`）・Z・AA（`=ROUNDUP($E*G,0)`）だけ自行で再計算する構造。元シート側でGを直接入力で上書きしたり式を消したりすると、まとめの再計算値と元シートの値が食い違い、②総額（＝検証A/Bの基礎）が誤る。そこで (1)まとめ参照式の行・列・シートずれ (2)元シートのデータ行（依頼NO or 契約NOあり）の取込漏れ (3)元シート・まとめの G/AA 列の式崩れ（空欄・直接入力・別式） (4)行別の まとめAA vs 元シートAA の金額差 を検出し、シート別の合計比較表とともに出力する。**要修正（金額差・参照ずれ・未取込）が1件でもあれば警告を出し、②を直して再実行する**のが前提。
- **検証Bの枝番統合（自動消込）**: ③が枝番（例 `C8-3-1`）に分割計上し②は親依頼NO（`C8-3`）に一本で計上しているケースでは、③の親+枝番合計が②の親と一致すれば親・枝番とも「**枝番統合一致**」（緑・要確認対象外）と判定する。親だけで一致済みなら枝番は本当の③のみとして残す
- **検証Bの累計比較（月ずれ自動消込）**: 当月単月の突合で不一致・片側のみになった依頼NOは、②の全月度（過去月+当月+翌月）の累計と③の全照会月の累計を比較し、**累計が一致すれば「月ずれ解消」**（計上月ずれと判明）として要確認から除外する。アラジンフォルダに複数月の照会ファイル（各月の「対象年月」で自動判別）を置くほど精度が上がる。解消しなかった不一致にも備考に累計内訳（②累計/③累計/累計差）を表示する
- **過去月突合**: ①のみに存在する契約NO（依頼NO空欄になるもの）は前月以前の依頼を金額修正するデータが含まれるため、フォルダ内の過去月②ファイルの「東レまとめ」とも突合し（新しい月から順に検索）、存在すれば「前月調整」と判定する
- **翌月突合**: 過去月にも無かった①のみの契約NOは、翌月以降の②ファイルとも突合する（近い月から順に検索）。翌月の②に記載されていれば「**翌月記載**」＝②の記載月誤りと判定。①は当月検収なので本来は当月の②に記載すべきもの → **②の2ファイル修正（当月へ追記・翌月から削除）が必要**であることをレポートに明記する

## 実行方法

```bash
python .cursor/skills/kouchin-consistency-check/scripts/verify_kouchin.py                  # 国分工場
python .cursor/skills/kouchin-consistency-check/scripts/verify_kouchin.py --factory konan  # 湖南工場
```

両工場の月次報告が必要なときは2回実行し、それぞれの結果Excel（`検証結果_国分工場_*.xlsx` / `検証結果_湖南工場_*.xlsx`）を使う。国分の結果Excelは最新の `検証結果_湖南工場_*.xlsx` から湖南の数字を取り込み、両工場の表付き本文を生成する（湖南結果が無い場合は湖南行を0埋め）。湖南実行のメール下書きは自工場の行のみ。同じ内容を `検証結果_<工場>_*.html` にも保存する。

PowerShell が UNC パス（`\\192.168.0.101\...`）をカレントにできず実行できない場合は、ローカルフォルダをカレントにしてスクリプトを絶対パスで指定する（`--base` は既定でスクリプト位置から解決されるので不要）。コンソール出力を確認する際は `[Console]::OutputEncoding = [Text.Encoding]::UTF8; $env:PYTHONIOENCODING='utf-8'` を先に設定しないと日本語が化ける。

- ファイルを自動検出して実行する（スクリプトの相対位置から●自動検証フォルダを解決）。
  - **対象月は①のファイル名 `RVSHEETyyyymm` を基準**とする（①はファイル名の年月が最大のものを選択）。①は両工場共通で、入庫場所（A010/A010P）で絞り込む。
  - ②は年月が**①の対象月と一致するものを当月**、それより古い年月を**過去月ファイル**、新しい年月を**翌月ファイル**として使用（同一年月に複数版があれば更新日時最新）。年月は国分=ファイル名の「yyyy年m月度」、湖南=東レシート先頭セルの「yyyy年m月度」。翌月ファイル（9月度等）が先行作成されていても誤選択しない。対象月の②が無い場合はエラーで停止する。**過去月は直近6か月まで**（`PREV_MONTH_WINDOW`）。湖南の年度フォルダには1年分以上があり、依頼NO（`C8-1`）は年を含まないため、12か月以上読むと前年同月と衝突して検証Bの累計比較が狂う。6か月あれば前月調整の判定には十分で、それより古い契約は「①のみ」として調査対象に残る。
  - ③は**シート内の「対象年月」が①の対象月と一致するファイル**のうちファイル名 `_yyyymmdd_hhmmss` が最新のものを選択（ファイル名の年月ではなく**内容の対象年月で判定**し、同一年月が複数あれば最新を採用。他月の照会ファイルが混在しても誤選択しない）。明示指定時に対象年月が不一致なら中断（`--force` で警告のみで続行）。**他月の照会ファイルも自動で読み込み、検証Bの累計比較に使用する**。照会取得日が対象月の月中（28日より前）の場合は途中実績である旨を警告する（当月ファイルが途中実績のときは②のみ・検証C不一致が実態より多く出るため、警告の先頭に出し、月末確定後のファイルを置いて再実行するよう促す）。
  - 湖南の②③月次処理ファイルは●自動検証の外（湖南共有）を参照する。②③はフォルダにアクセスできなければエラーで停止する。コンソール冒頭とサマリの「使用ファイル」に参照フォルダを表示する。
  - 湖南は加えて東レ月次処理ファイルルートの `yyyy年\` から対象月の月次処理ファイルを選び検証Cに使う（無ければ警告してスキップ）。
- コンソールにレポートを出力し、`●自動検証\検証結果_<工場>_タイムスタンプ.xlsx` に結果Excelを保存する。保存後、同工場の**最新以外**の `検証結果_*.xlsx` / `.html` は `過去検証結果\` へ自動移動する。
  - シート構成: 「サマリ」（KPIカード6枚・総額・検証件数・（湖南のみ）検証C表・（国分のみ）検証D集計表・報告用内訳・警告赤帯・凡例・使用ファイル）/「レポートの見方」（セルベースのフローチャート図解ガイド）/「検証A_契約NO(①vs②)」/「検証B_依頼NO(②vs③)」/（国分のみ）「検証D_②まとめ整合性」/「報告メール下書き」（**HTMLメール本文**。国分の結果では最新の `検証結果_湖南工場_*.xlsx` から湖南の数字を取り込み、両工場の表付き本文を生成。湖南結果が無い場合は湖南行を0埋め。湖南実行は自工場の行のみ。同じ内容を `検証結果_<工場>_*.html` にも保存し、ブラウザで開いて Ctrl+A→C→Outlookへ貼り付け）+ 元データのコピーシート（「①東レCSV原本」、②原本（国分=「②東レまとめ(当月)」、湖南=「②東レT.V.C(当月)」「②東レY.S(当月)」「②東レW.E..(当月)」）、「③アラジン原本」、および前月調整・翌月記載の根拠になった他月の②原本）
  - 検証Aシートの列: 契約NO / 依頼NO / ①東レ金額 / ②金額 / 差額(①-②) / **報告計上額**（「報告する過不足」への各行の計上額。列合計がKPIと一致） / 判定 / 備考
  - 検証Dシートの列（国分）: 場所(シート!行、例 `東レまとめ!225 ↔ 東レV.C!83` / `東レW.E!G23`) / 依頼NO / 契約NO / まとめAA / 元シートAA / 差額(まとめ-元) / 判定 / 内容・対処。判定は 赤=**金額差・参照ずれ・未取込**（②の集計誤り・要修正）、橙=**式異常**（元シートG/AA列が空欄や別式）、黄=**直接入力**（式が値で上書きされた箇所・注意）。問題が無ければ「問題なし」1行だけのシートになる
  - 明細シートは要確認度順（不一致→翌月記載→片側のみ→前月調整・前月過不足・手動判定→月ずれ解消・枝番統合一致→形式不正→一致）に並び、赤=不一致、橙=翌月記載、黄=片側のみ、青=前月調整、淡青=前月過不足、薄紫=手動判定、緑=月ずれ解消・枝番統合一致、灰=形式不正で行を色分け。判定列は色覚多様性・モノクロ印刷に配慮した濃色文字。オートフィルタ・備考折り返し・負数赤表示付き。金額は書き込み時に小数2桁へ丸め、整数なら整数表示（合算で生じる `-0.00` などの浮動小数誤差を消す）。

### デザイン仕様（結果Excel）

- **フォント**: 全シート BIZ UDPゴシック 10.5pt（`DEFAULT_FONT` 書き換え + テーマ差し替えで無指定セルにも適用）。金額・件数セルのみ等幅版の BIZ UDゴシック（プロポーショナル版は数字「1」だけ幅が狭く桁が縦に揃わないため）。

## レポートの読み方

- **金額不一致**: 両ソースにキーが存在するが金額が許容差を超えて異なる。最優先の確認対象。次月調整の報告対象（当月差異）。
- **前月調整**: ①のみだが過去月の②まとめに契約NOが存在。過去依頼の金額修正データ。依頼NO列に「(7月)依頼NO」のような月ラベル付き依頼NO、備考に当時のAA金額と①との差額を表示。要確認件数には含めない。
- **前月過不足**（淡青）: 前月の工賃差検証で東レへ次月修正を依頼したが、当月①CSVに調整行がまだ来ていない差額（`前月過不足.csv`）。**①列は空**（当月①にデータ無し）、**②列にプラス差（長岡−東レ）**、差額・報告計上額=前月の①−②。備考に前月当時の①②金額を記す。マイナス側の調整は①取消行として「前月調整」に出るが、プラス側（長岡>東レ）は①に現れないためこちらで補う。要確認・判明済みの両方に数える。メール下書きにも「前月調整分に①未反映のプラス差を含む」旨を注記する。
- **①正(手動) / ②正(手動)**（薄紫）: `手動判定.csv` で当月・当工場・当該契約NOにつき「正しい側」を人が指定した不一致。要確認件数には含めず「判明済み」に数える。
  - **①正** = 東レ金額が正しい → ②を①金額に修正する。東レへは報告しないため「報告計上額」は空欄、報告用内訳では「手動判定①正(②要修正)」として別枠に分解する（②修正後は②実売上に入る）。
  - **②正** = 長岡側が正しい → 東レの誤りとして報告する。「報告計上額」は差額①-②で、当月差異に含まれる（件数は「うち手動判定②正 n件」と併記）。
  - 備考に「手動判定: 今回(yyyy年m月度)に限り①東レを正とする → ②を①金額 xx円 に修正する…/ 理由: …」と、csvの理由欄をそのまま転記する。
- **翌月記載**（オレンジ色）: ①（当月検収）のみだが翌月の②まとめに契約NOが存在。②の記載月誤りで、**②の2ファイル修正（当月分へ追記・翌月分から削除）が必要**。備考に翌月側の依頼NO・AA金額・①との差額と修正指示を表示。②修正後に本検証を再実行して数字を確定させる。要確認件数に含める。
- **月ずれ解消**（緑色）: 検証Bで当月単月では差異があるが、②の全月度累計と③の全照会月累計が一致したもの。計上月ずれと判明したため要確認対象外。備考に累計金額と構成月を表示。③照会が月途中取得の場合は解消数が少なくなる（月末確定後の再取得で改善）。
- **①のみ / ②のみ / ③のみ**: 片方にしかキーがない。計上月ずれ（前月検収・翌月繰越）や記載漏れの可能性。①のみは過去月・翌月にも無かったもの（②への記載漏れの疑い）。
- **金額0円の行（無効行）**: 両側とも0円の一致行、および0円の片側のみ（取消済み・翌月分の予定行など）は無効行として検証A/Bシートに出力しない。除外件数はコンソールの結論とサマリ下部（「金額0円の無効行(出力対象外)」）に表示する。
- **C列が契約NO形式でない行**: 契約NOは**ハイフン無し7桁英数字**（例 `191352R`）。②のC列の「9月」「キャンセル」等のメモ書きは突合・Excel出力とも除外し、コンソールに件数のみ表示する。ただしAA列に金額が入っている場合だけは記入漏れの疑いがあるため「形式不正」としてExcelに記録する。
- **枝番統合一致**（緑色）: ③が枝番（例 `C8-3-1`）に分割計上し、親依頼NO（`C8-3`）に合算すると②と一致したもの。親・枝番の両行に付き、備考に合算式を表示。要確認対象外。合算しても一致しない枝番は従来どおり③のみとして残り、備考に親+枝番の合算参考値を注記する。
- **検証C（湖南のみ）**: 月次処理ファイルの東レ合計と本検証の総額の照合表。「一致」「内訳で説明可」（売上明細③と①の差が報告用内訳で説明できる）以外の「不一致」「要確認」「読取不可」は警告にも出る。
- **検証D（国分のみ）**: ②「東レまとめ」と元4シートの整合性。サマリに元シート別の「まとめAA計 / 元シートAA計 / 差」の表、検証Dシートに箇所別の明細を出す。
  - **金額差**: 同じ行なのに まとめAA ≠ 元シートAA。典型は「元シートのG列が `47.333…` のような割り切れない単価合計で、まとめ側だけ `47.33` に直接入力した」ケース（ROUNDUP で 85,200 vs 85,194 のような差）。元シートの単価欄（H〜X）を小数2桁に丸めるか、まとめの直接入力を式に戻して両者を一致させる。
  - **参照ずれ**: まとめの1行の中で参照先のシート・行・列が混在している、または G/Z/AA の自行式が他行を参照している。行の挿入・削除やコピペで起きる。
  - **未取込**: 元シートに依頼NO/契約NOが入ったデータ行があるのに、まとめのどの行からも参照されていない（加工賃がまとめから漏れる）。
  - **式異常**（橙）: 元シートの G または AA が空欄・定型と異なる式。G空欄は加工賃が0円になる（例: `東レY!G40` が空欄で AA=0 だったケース）。まとめと元シートの両方が同じ非定型式（例: 7月度の `=ROUNDUP($E101*G101,0)+1` という1円手調整）なら金額差にはならず注意のみ。
  - **直接入力**（黄）: G/Z/AA が式でなく値。元シートのGを値にすると、まとめ側は H〜X の合計で再計算するため食い違う（例: `東レW.E!G23=30` を直接入力、まとめは `SUM(H:X)=17` → 23,400円差）。単価を変えるときは元シートの H〜X 列（種類別単価）を直すのが正しい修正。
  - 要修正（金額差・参照ずれ・未取込）が1件でもあると【警告】に出る。②が土台なので、検証A/Bの結果を読む前に検証Dを0件にする。

### 備考欄の自動注記

- **契約間振替の疑い**: 検証Aで同一依頼NO内の不一致どうしの差額が相殺関係（ネット差額がグロス差額の半分未満）にある場合に注記。契約NO間の数量振替ミスの典型パターンで、ネット差額のみが実質の過不足。
- **計上月ずれの可能性**: 検証Bで依頼NOの月番号（例 `Y7-`系）が対象月と異なる場合に注記。③アラジンは単月照会のため、過去月依頼の差異は計上月ずれの可能性が高い（真の異常と区別して優先度を下げられる）。
- **①入庫日**: 検証Aの①のみ・前月調整の行に①CSVの入庫月日（yymmdd）を自動転記。原因調査の起点。
- **①に取消行(H列「-」)あり**: ①CSVのH列が「-」の行はマイナス（取消）行。該当契約NOの行（不一致・前月調整・①のみ）の備考に行番号・金額・純額を注記する。検収→取消で純額0円になった契約は無効行として出力対象外になり、翌月②に記載があっても「翌月記載（記載月誤り）」とは判定しない（①で当月検収が消えているので翌月計上が妥当）。
- **①小計(T行)から除外の疑い**: ①CSVのブロック小計差と同額の契約NOが対象工場のものなら、検証Aの当該行（①のみ・不一致）の備考に注記。H列符号を正しく反映していれば通常は発生しない。

### 警告（サマリの【警告】欄・コンソール冒頭）

- **①CSVブロック小計(T行)との検算不一致**: H列符号を反映したデータ行合計とT小計が合わないブロックを検出。H列以外の符号表現やフォーマット変更の疑いがあり、①総額の信頼性に関わるため最優先で確認する。1つのTブロック内に A010 と A010P の行が混在するためブロック内の入庫場所を全て列挙し、差額と同額の契約NO（入庫場所付き）があれば警告文に示す。両工場の実行で同じ警告が出るのは仕様。
- **①CSV H列に想定外の値**: H列が空欄・「-」以外の行はプラスとして集計したうえで警告する（新しい符号表現の検出用）。
- **②「東レまとめ」が元4シートとずれています（国分）**: 検証Dの要修正件数と加工賃合計の差を示す。②総額の信頼性に関わるので、②を修正して再実行する。
- **検証Dをスキップしました（国分）**: openpyxl で②を開けない、またはシート構成（東レまとめ + 東レT/東レV.C/東レY/東レW.E）が想定と違う場合。
- **手動判定.csv: 契約NO xxx は当月の検証Aで不一致ではありません**: csvに書いた契約NOが当月は片側のみ・存在しない場合（契約NOの誤記の疑い）。①②とも存在して既に一致している場合（②を修正して差が消えた後）は警告にせず、コンソール冒頭に「既に①②一致のため不要 n件」と情報表示するだけ。csvの行は履歴として残してよい。ヘッダー不正・対象月が読めない・正とする側が①②以外の行は警告して無視する。
- そのほか金額を数値化できず除外した行、AA列が数値でない行、対象月の不一致など「静かなデータ落ち」をすべて警告として表示する。

## データ仕様の注意点（スクリプト変更時に必読）

- ①CSVは **cp932** エンコーディング。発注No.が `\d{3}-\d{3}[A-Z0-9]` 形式の行だけがデータ行（小計行 T/GT・飾り行・`#VALUE!` 行は形式不一致で自動除外）。
- ①の**H列（8列目、ヘッダーは「品名」）は符号欄**。「-」が入った行は取消（マイナス）行で、金額列（J列）は絶対値のまま入っているため**符号を反転して集計**する。T行の小計はこの符号込みで計算されているので、反転後はすべてのTブロックで検算が一致する。反転しないと同一契約NOの検収行と取消行が二重計上され（例: 190765Y 18,560+18,560=37,120 → 正しくは 0）、①総額が過大になる。
- ①のA列（入庫場所）は「N122B/N122F」の生産場所行の直後のデータ行にのみ入り、以降の行は空欄のまま引き継がれる。**A010=国分工場、A010P=湖南工場**で、工場プロファイルの既定値で絞り込む（`--basho`で上書き可）。対象外の入庫場所の金額はレポート冒頭とサマリシートに表示される。Tブロック（`*****` 行〜T行）は入庫場所ごとではなく両工場の行が混在する。
- 国分②のA列は「Ｔ7」のように**全角・半角が混在**する。契約NO・依頼NOは NFKC 正規化（全角→半角）+大文字化してから比較する。B列は数値セルなので `72.0` → `72` に整数化する。
- 国分②のデータは6行目以降。AA列 = 27列目（0始まりで26）。同一契約NO・同一依頼NOが複数行に分かれるため集計して比較する。
- 国分②「東レまとめ」の構造（検証Dの前提）: A〜F・H〜X 列は `=東レT!A6` 形式の他シート参照（`=+'東レV.C'!A6` のように `+` やクォート付きもある）、G=`=SUM(H:X)` **または** `=東レT!G6` のように自行の元シート行の同列を参照する式（2026年8月度V01の修正で採用。元シートGを直接入力してもまとめと食い違わなくなる。参照先が別シート・別行・別列なら「参照ずれ」）、Z=`=ROUNDUP($D*G,0)`、AA=`=ROUNDUP($E*G,0)`（Z/AAも同様に元シート参照式なら可）、AB〜AR・AT〜BJ は種類別の金額・数量の式。元4シートも同じ列構成で、合計行は C列が「加工量合計」「加工賃合計」「営業入庫量」。まとめの行は元シートを T→V.C→Y→W.E の順にブロックで並べるが、元シートの空行を飛ばすことがあるので**行番号の連番ではなく参照式から対応行を求める**（`check_matome`）。月によっては A〜X が式でなく値貼り付けになっているファイルもあり（6月度）、その場合は参照が取れないため検証Dは「参照式が無い(値貼り付け)」の理由付きでスキップし警告に出す。元シートのデータ行の定義は「B列（連番）と A列が両方ある、または C列に合計ラベル（加工量合計/加工賃合計/営業入庫量）以外の値がある」行。A列に `T7` だけ入った空テンプレート行や、まとめ末尾が元シートの合計行を参照している箇所は対象外（7月度で誤検知した実績あり）。
- 検証Dの定型式チェックは空白を除いた完全一致で行う。定型式を変えるときは `_matome_expected()` を更新する。
- 湖南②（加工賃試算.xlsm）は3シートとも同じレイアウト: 1〜7行目はオートフィルタの抽出条件（依頼NOの `*T*` `*V*` 等・調整納期の月範囲）、8行目ヘッダー（A「加工依頼No.」/C「契約No.」/D「入庫数量」/V「加工種類別 加工賃」合計）、9行目=種類別小見出し、10行目=単価、11行目=合計行、12行目〜データ。列位置はヘッダー文字列で検出する。金額は小数（単価×数量の端数）を含むことがあるため、一致判定は許容差0.5円で行い、Excel出力は2桁丸め。「東レ合計」「総合計」シートは集計式が未計算（0）のことがあるので使わない。
- 湖南③には 東ﾚ(株)自材部(049006) のほか 東ﾚﾍﾟﾌ加工品(株)=TPI(049052)・大和リース等の得意先が混在する。**得意先コード 049006 の行だけ**を東レ分として集計する（`_factories()['konan']['customer3']`）。
- 湖南 月次処理ファイル（xlsm）の「月次検証」シートは 1行目=区分見出し、2行目=ヘッダー（得意先/得意先ｺｰﾄﾞ/月次実績①/月次実績表②/売上明細③/差異…）、3行目=東レ行。ヘッダー内の丸数字は NFKC 正規化で `1` `2` `3` になるため、検索キーも正規化してから部分一致で列を特定する。
- ③はアラジン画面では横持ち表示だが、xlsxは縦持ち（1依頼NO×9項目の行）。画面の「太字セル」に相当するのは**項目「加工金額」行の「--合計--」列**。ヘッダー行は「依頼NO」「項目」を含む行を検索して特定する。
- ③のヘッダーより上の「対象年月 : yyyy年mm月」行で対象月を確認できる（レポートに表示）。
- 工場を追加・変更するときは `verify_kouchin.py` の `_factories()` にプロファイル（label/basho/dir2/dir3/dir_monthly/find2/read2/ym2/raw2/hl2/check_d/customer3/文言）を追加し、`dir2/dir3/dir_monthly` は●自動検証からの相対パスか絶対パス（UNC可。`resolve_dir` で解決）で指定する。②リーダーは `read_nagaoka`/`read_shisan` と同じ戻り値 `(依頼NO->金額, 契約NO->金額, 契約NO->依頼NO集合, 形式不正リスト, 警告)` を返すように書く。`check_d` は②内部整合性チェック関数（無い工場は `None`）で、`check_matome` と同じ `dict(rows, totals, n_map, skipped)` を返せばサマリ・検証Dシート・ガイドに自動で反映される。倉庫コードでは絞り込まない。

## 報告用内訳（東レ宛メール報告との対応）

サマリシートの【報告用内訳】は、東レへの月次報告メール（例:「実売上 − 前月調整分 − 当月差異」形式）の元数字になる。

```
①東レお支払データ = ②当月実売上 + 前月調整分 + 翌月記載 + 当月差異 + 手動判定①正 + 未解明(①のみ − ②のみ)
```

「翌月記載」は②の記載月誤りのため、②の2ファイル修正後は「②当月実売上」に移る（修正後に再実行して確定させる）。「手動判定①正」も同様に②側を直す区分で、東レへの報告には含めない（該当が無い月は行自体を表示しない）。

検算残差が0であれば上記区分の内部整合が取れている（ただし許容差内の微差・形式不正行の金額は分解に含まれない）。

**報告する過不足（当月）** = 当月差異 + 翌月記載 + 前月過不足 + ①のみ − ②のみ。これがメールで東レへ次月調整を依頼する金額で、サマリのKPIカードと報告用内訳に表示される。検証Aシートには「**報告計上額**」列があり、各行がこの金額にいくら計上されているかを示す（不一致行=差額①-②、翌月記載・①のみ行=①金額、②のみ行=−②金額、前月過不足行=前月の差額①-②、それ以外は空欄）。この列の合計が「報告する過不足」と一致するので、Excel上で列を選択すれば内訳を検算できる。結果Excelの「報告メール下書き」シートにこの数字を反映したメール文面が自動生成される（国分実行は湖南の最新結果を取り込み、無い場合は湖南行を0埋め。湖南実行は自工場の行のみ。国分→湖南の並びは実際のメールに合わせて固定）。

## 手動判定（`●自動検証\手動判定.csv`）

検証Aの不一致について「今回に限り①東レ金額を正しいとする」「この件は東レの誤りで確定」といった人の判断を残し、再実行しても要確認に出ないようにする仕組み。ユーザーから「この差額は①を正とする / ②を正とする」と指示されたら、**スクリプトを変えずに**このcsvに1行追加して再実行する。

```
工場,対象月,契約NO,正とする側,理由
国分工場,2026年8月度,189759V,①,1円差(①22302 vs ②22301)。今回に限り①東レ金額を正とする(2026-09-03 指示)
```

- 文字コードは UTF-8(BOM付き) で作成しているが、Excelで開いて「CSV」保存され cp932 になっても読める（utf-8-sig → cp932 の順で試す）。
- **工場**: `国分工場`/`湖南工場`（「工場」無しも可。空欄なら両工場に適用）。**対象月**: `2026年8月度` `2026-08` `2026/8` `202608` のいずれか。**必須**で、当月と違う行は無視されるため「今回に限り」の判断が翌月以降に持ち越されない。**契約NO**: ハイフン有無・全角半角は正規化される。**正とする側**: `①`/`1`/`東レ` または `②`/`2`/`長岡`。**理由**: 備考にそのまま転記されるので、誰の指示か・日付を書いておく。
- 適用対象は「当月の検証Aで両方に存在し金額不一致」の契約NOのみ。一致・片側のみ・翌月記載・前月調整には効かない（該当しなければ警告で知らせる）。検証Bの依頼NOには使えない。
- 判定結果の扱いは「レポートの読み方」の **①正(手動) / ②正(手動)** を参照。サマリの検証A欄に「手動判定済みの不一致 (対象外) n件」、実行条件欄（0円除外の下）に「手動判定: … 行を適用」、コンソールの検証Aに「▼手動判定済みの不一致」の一覧が出る。
- 過去月の行は消さず履歴として残す（他月には影響しない）。

## 前月過不足（`●自動検証\前月過不足.csv`）

前月の工賃差検証表で東レへ「次月度修正依頼」した差額のうち、当月①CSVに調整行がまだ来ていないものを載せる。マイナス側（東レ過払い）は①取消行として「前月調整」に自動で出るが、プラス側（長岡>東レ＝東レの支払不足）は①に現れないため、ここに明示登録しないと報告する過不足から落ちる。

```
工場,対象月,契約NO,依頼NO,①東レ金額,②長岡金額,理由
国分工場,2026年8月度,188763B,Y7-35,1980,10879,2026年7月度工賃差検証。次月修正依頼済みだが8月①に未反映
国分工場,2026年8月度,188928R,Y7-51,73980,74000,2026年7月度工賃差検証。次月修正依頼済みだが8月①に未反映
```

- **対象月**は調整を反映すべき当月（例: 7月差 → `2026年8月度`）。①②金額は前月当時の金額。差額(①−②)が報告計上額になる（上例は -8,899 / -20）。
- 検証Aシートでは **①列を空・②列にプラス差（長岡−東レ、上例 +8,899 / +20）** とし、備考に前月当時①②を書く。メール本文にも「前月調整分に①未反映のプラス差を含む」と注記する。
- 既に前月調整（当月①に調整行あり）や当月①に存在する契約NOは重複を避けてスキップし警告する。
- 東レが翌月以降に調整行を送ってきたら csv から該当行を削除（または対象月を変えないまま残しても翌月実行では無視される）して再実行する。

## 検証後のフォロー

レポート出力後、不一致件数と差額の大きい上位項目を要約してユーザーに提示する。特に検証Aの不一致（東レ検収と長岡明細の食い違い）は支払金額に直結するため必ず言及する。【警告】がある場合（特に①CSVの小計検算不一致、国分の検証D要修正）は最初に伝える。報告用内訳の数字（実売上・前月調整分・当月差異）も併せて提示すると月次報告メールの作成に使える。「両工場」「全体」の検証を依頼されたら国分・湖南を両方実行し、メール文面用に2工場分の数字を並べて提示する。

### ②を修正して再実行するときの流儀（国分）

- 検証Aの不一致の原因が②側（東レまとめ）の場合、**まとめのセルを直接書き換えるのではなく元シート（東レT/V.C/Y/W.E）の単価欄 H〜X を直す**。まとめは元シートの参照＋再計算なので、元シートを直せばまとめも追従し、検証Dの「直接入力」も残らない。
- 単価合計Gが `47.333…` のように割り切れない場合、東レの支払額は小数2桁の単価で計算されている（`1800 × 47.33 = 85,194`）。元シート側の単価を2桁に丸めれば まとめ・元シート・① の三者が一致する。
- ユーザーが②を修正したと言ったら、そのまま再実行して「検証Dの要修正0件」「検証Aの不一致件数・当月差異の変化」を報告する。
