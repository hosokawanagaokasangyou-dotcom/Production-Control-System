# 後加工工賃 工程別・シート区分別 月トレンド（設計）

日付: 2026-09-07  
ステータス: デザイン承認済み（実装前レビュー待ち）  
関連: 検証スキル `kouchin-consistency-check` とは別スキル

## 1. 目的・範囲

### 目的

国分工場・湖南工場の長岡系明細（データソース②）から、**加工種類（工程）別**および**シート区分別**の**加工賃・加工量**の月次トレンドを、1つのExcelブックで横断比較できるようにする。

### 含む

- データ取得（②のみ）
  - 国分: `工賃明細2026年度（令和8年度）` と `工賃明細２０２５年度　(R7年度)` を絶対パスで直接参照（`common.KOKUBU_MEISAI_DIRS`）。同一年月は更新日時最新。`.lnk` は使わない
  - 湖南: ユーザー提示の `湖南工場\試算\2026年度試算　湖南.lnk` が指す実体。スクリプトは `.lnk` を読まず、検証スキルと同じ `KONAN_SHISAN_ROOT`（湖南共有の後加工試算ルート）およびその配下の `yyyy年度試算　湖南` を参照する
- 軸: 加工種類別 ＋ シート区分別
- 指標: 加工賃・加工量
- 期間: 直近 N か月（既定 6、実行時 `--months` で変更）
- 出力: 表 ＋ 折れ線グラフ ＋ 簡易サマリ（前月比・構成比）を **1ブック**（工場横断比較あり）
- 成果物: プロジェクトスキル `kouchin-monthly-trend` ＋ `scripts/trend_kouchin.py`

### 含まない

- ①東レCSV・③アラジンとの突合・矛盾判定・報告メール（検証スキルの範囲）
- 工程名の強制マッピング（工場横断で別名を無理に統合しない）

## 2. データ取得・指標定義

### データ源

| 工場 | 参照先 | 月次ファイルの選び方 | 集計対象シート |
|------|--------|----------------------|----------------|
| 国分 | `KOKUBU_MEISAI_DIRS`: `...\後加工工賃明細\工賃明細2026年度（令和8年度）` と `...\工賃明細２０２５年度　(R7年度)`（絶対パス直参照） | `*後加工工賃明細*.xls*`。年月はファイル名。同一年月は更新日時最新 | **東レまとめ**（種類別列はヘッダー行の工程名。金額 AB〜AR、数量 AT〜BJ。単価列 H〜X は参照用） |
| 湖南 | `KONAN_SHISAN_ROOT` = `\\192.168.0.101\共有フォルダ\湖南工場\湖南共有\002  加工G\000  後加工業務\2 後加工試算`（空白は半角2つ）。直下の作業中 `月度加工賃試算.xlsm` と `yyyy年度試算　湖南\m月度加工賃試算.xlsm` | 年月は東レシート先頭付近の「yyyy年m月度」。同一年月は更新日時最新。`temp`・`バックアップ`・旧年度表記は除外 | **東レT.V.C / 東レY.S / 東レW.E..**。ヘッダーの加工種類列と数量列。合計加工賃は「加工種類別 加工賃」列（検証の V 列相当） |

### 期間

- 基準月 = `--factory` で選んだ工場の②から読めた年月の**最大値**（両工場なら国分・湖南の最新月の大きい方）
- その月から遡って N か月（既定 6）を対象とする
- 片方の工場に無い月は空欄（グラフは欠損）

### 指標

| 指標 | 国分 | 湖南 |
|------|------|------|
| 加工賃（種類別） | 東レまとめの種類別金額列（AB〜AR）を工程名ごとに月合計 | 各東レシートの種類別金額列を工程名ごとに月合計（3シート合算は種類別横断用。シート区分別では合算しない） |
| 加工量（種類別） | 東レまとめの種類別数量列（AT〜BJ） | 各東レシートの種類別数量列 |
| 加工賃（シート区分） | 元シート 東レT / 東レV.C / 東レY / 東レW.E の加工賃合計（AA 相当）。検算用にまとめ AA 総額も保持可 | シートごと「加工種類別 加工賃」合計列 |
| 加工量（シート区分） | 各元シートのデータ行の数量列（ヘッダーで特定、例: 入庫数量/加工量） | 各東レシートの数量列（ヘッダーで特定、例: 入庫数量） |

合計行・ラベル行（「加工量合計」「加工賃合計」「営業入庫量」等）は集計対象外。契約NO形式不正行でも種類別数値があれば種類別集計には含める（キー突合はしないため）。

### 横断比較

- 工程名は各工場ヘッダーの文字列をそのまま使用
- 同名工程のみ横断シートで横並び。片方のみの工程はその工場列だけ数値
- シート区分名は工場ごとに異なるため、横断では「工場＋シート名」で並記し、統合しない

## 3. Excel構成・実行方法

### 出力パス

- `●自動検証\月トレンド_yyyyMMdd_HHmmss.xlsx`
- 保存後、同種の最新以外を `過去月トレンド\` へ退避（無ければ作成）

### シート構成

| シート | 内容 |
|--------|------|
| サマリ | 対象期間、使用ファイル一覧、工場別・最新月の総額、前月比、構成比トップ、警告 |
| 横断_加工賃 | 行=工程（＋合計）、列=月。工場並記。折れ線グラフ |
| 横断_加工量 | 同上（量） |
| 国分_種類別 | 工程×月の加工賃／加工量マトリクス＋グラフ |
| 国分_シート区分 | 東レT / V.C / Y / W.E ×月＋グラフ |
| 湖南_種類別 | 工程×月＋グラフ |
| 湖南_シート区分 | 東レT.V.C / Y.S / W.E.. ×月＋グラフ |
| 前月比・構成比 | 最新月の前月比％、工程別構成比％（工場別） |

見た目は検証結果Excelに寄せる（BIZ UDPゴシック、金額は BIZ UDゴシック、タブ色分け）。

### 実行例

```bash
python .cursor/skills/kouchin-monthly-trend/scripts/trend_kouchin.py
python .cursor/skills/kouchin-monthly-trend/scripts/trend_kouchin.py --months 12
python .cursor/skills/kouchin-monthly-trend/scripts/trend_kouchin.py --factory kokubu
python .cursor/skills/kouchin-monthly-trend/scripts/trend_kouchin.py --factory konan --months 6
```

オプション:

| オプション | 意味 | 既定 |
|------------|------|------|
| `--months N` | 直近月数 | 6 |
| `--factory kokubu\|konan\|both` | 対象工場 | both |
| `--out path` | 出力先 | ●自動検証直下の自動名 |
| `--base path` | ●自動検証ルート | スクリプト位置から解決 |

依存: `python-calamine`（読取）、`openpyxl`（書出・グラフ）。

### エラー・警告

| 状況 | 挙動 |
|------|------|
| 対象月の②が片方の工場に無い | 警告して続行（空欄） |
| 対象工場すべてで読める月がゼロ | エラー停止（`--factory both` なら両方がゼロのとき） |
| 湖南ルート不通 | `--factory` に湖南が含まれる場合は湖南をスキップして警告。国分データがあれば続行。湖南のみ指定ならエラー停止 |
| 工程ヘッダーが月により増減 | 全期間の工程名の和集合で行を構成 |
| シート欠落 | 当該シート区分を警告付きで欠落 |

## 4. スキル配置・コンポーネント

### ディレクトリ

```
.cursor/skills/kouchin-monthly-trend/
├── SKILL.md
└── scripts/
    └── trend_kouchin.py
```

### SKILL.md

- `name`: `kouchin-monthly-trend`
- `description`（第三者視点・トリガー語を含む）: 国分・湖南の後加工明細（②）から工程別・シート区分別の加工賃・加工量の月次トレンドExcelを生成する。ユーザーが「工程別の月トレンド」「加工量の推移」「種類別トレンド」「月次推移をExcelで」「シート区分の推移」などを依頼したときに使用する。金額突合・検証は `kouchin-consistency-check` を使う。
- 検証スキルとは独立。突合・メール下書きは書かない
- データ源・列定義・コマンド・出力シートの見方を簡潔に記載

### スクリプト内部の単位

| 単位 | 役割 |
|------|------|
| 工場プロファイル | パス、シート名、種類列／数量列の読み取り方 |
| 月次スキャナ | 直近 N か月の②ファイル一覧 |
| 集計器 | 月×工程×（賃/量）、月×シート区分 |
| Excelライター | 表・グラフ・サマリ・過去退避 |

`verify_kouchin.py` は import しない。パス定数・年月正規表現・湖南ルートは同値を本スクリプト内に持つ（検証改修の副作用を避ける）。

### 成功条件

1. 既定 6 か月で1ブックが開ける
2. 国分・湖南の種類別／シート区分と横断比較が見える
3. 前月比・構成比と折れ線グラフがある
4. 「月トレンド」「工程別推移」等の依頼で本スキルが選ばれる

## 5. 実装方針（承認済みアプローチ A）

検証スキルと同型の **プロジェクトスキル + 固定Pythonスクリプト**。エージェントはスキルに従いスクリプトを実行し、結果Excelの要点をユーザーに返す。
